# 无障碍主导、视觉补盲（1.2.0）

## 无障碍可以获取什么

本 App 读取前台目标应用的可见无障碍节点；平板上也合并同一应用的多个窗口，不主动遍历其他分屏应用。

| 内容 | 当前处理 |
| --- | --- |
| 应用包名、屏幕尺寸、窗口 | 用于确认当前目标及坐标范围 |
| 控件文字、内容描述 | 组成精简标签；文字子节点尽量合入可点击父节点 |
| 控件编号、资源 ID、类名、位置 | 完整数据留在本机；默认仅发短编号，按需返回有限详情 |
| 可点击、长按、输入、滚动、启用、选中、勾选状态 | 用短标志表示；原始节点在执行前再次核对 |
| 内容变化、滚动、文字及窗口事件 | 帮助等待界面短暂稳定；不把每个事件都发给模型 |

这些都是目标 App **愿意暴露的界面信息**，不是它的内部全部数据。不能直接获取私有数据库、全部聊天历史、登录令牌或尚未显示的内容。
自绘、游戏、图片中的字、部分 WebView 可能缺少节点；也可能漏掉隐私内容的语义。密码节点及子树、锁屏和助手自身界面被排除，不尝试绕过系统保护。

## 低开销执行循环

1. `phone_status` 检查连接；`phone_apps(query)` 按名字查包名，避免列出全部 App。
2. `phone_observe` 默认最多发送 48 行 `[id,flags,label]`，不反复发类名、资源 ID 或坐标。`query` 定位文字，`detail=true` 按需提供有限原始详情。
3. 优先用 `snapshot/node_id` 执行一个动作。`phone_act` 成功后等待约 0.3–1 秒并直接附带 `ui`，不需要机械地再调用一次 observe。
4. 相同语义场景可回复 `unchanged`，复用上一份节点编号，但必须使用回复中的**新 snapshot**。目前连续复用一次后会重发完整精简视图，避免丢失基础信息。
5. 当前任务的过时控件列表会从后续模型上下文中裁剪；保留最近两份完整视图及后续复用回复，保留所有工具调用/结果配对及执行结果。原有本地历史不删除。
6. 同一动作反复成功但场景无变化时，阻止继续重复。`ok=true` 只代表系统接受动作，不证明任务完成；`unchanged` 也不证明所有像素没变化。

完整原始树仍受最多 220 个保留节点、2000 次遍历及深度上限限制；默认精简文本也有长度限制。超出时要过滤、滚动或局部观察，而非假设已经看到全部内容。

## 按需视觉

只有无障碍定位不足时才调用 `phone_vision(query, region?)`；`region` 为屏幕像素 `[left,top,right,bottom]`。

- **独立许可默认关闭**：在设置中阅读说明后开启，还需云端处理许可和设备控制许可。没有替用户开启，也没有替用户修改系统无障碍权限。
- 默认每任务最多尝试 3 次，可设为 1–5 次；已获授权后的失败捕获也计入尝试预算。只允许单独调用，不与动作或其他工具混批。
- 利用 Android 11+ 无障碍截图能力，不引入 OCR 库。裁剪到允许的应用区域、遮蔽已识别的其他窗口，最长边 1024，JPEG 65，模型输入 `detail=low`。
- 局部裁剪有助于读小字。低细节仍可能误读，并不保证与原屏幕同等清晰。
- JPEG 和 base64 只用于内存中的下一轮模型请求。图片放在所有工具结果之后的 `user` 内容块中，推理结束或出错后移除图片块；不写聊天数据库或磁盘，不跨任务重用。
- 模型的文字解释及工具元数据可能进入本地历史；“不保存图片”不代表“对话不含私人内容”，也不代表服务商不保留请求。
- 视觉点击需要本图的 `vision_id`、图内归一化 `vx/vy`（0–1000）和目标说明，并**逐次人工确认**，不受普通界面自动授权豁免。原生模型工具不接受无来源的像素 tap；旧 loopback 接口仍默认关闭。
- 点击前重新本地截图，核对应用、裁剪、窗口区域和 JPEG 哈希，画面变化就拒绝；帧超过 90 秒也拒绝。动态图、动画等可能频繁失效，此时重观察或交用户，不能盲点。

锁屏、黑屏、助手自身窗口、无法核对的窗口、已识别的密码/验证码/付款页面、银行/支付/系统授权应用会拒绝截图；Android 拒绝系统保护窗口时不会换手段绕过。
**敏感页面和其他窗口识别是尽力而为，不能保证完整遮蔽一切私人内容**，尤其是缺少语义的自绘界面或未被系统列出的覆盖层。不要在隐私页面开启无人值守视觉。
上传后再关闭许可不能撤回已经发出的请求。系统权限变更、旋转与动态页面的完整设备矩阵仍需实测。

## 模型与计量

官方 `https://api.deepseek.com` 的 `deepseek-flash` 请求显式使用 `thinking:{type:"disabled"}`，减少逐步执行中默认思考和回传推理的开销；复杂规划也可能因此失去深度推理的优势，不宣称所有任务都更准确。
其他模型/代理不发送该厂商参数；若修改模型，必须自行确认其图片输入能力。

设置页的最近任务指标包括模型请求数、服务商返回的 prompt/completion token、原始/精简 UI 字符数及截图尝试数。流式累计 usage 只计一次。
未返回 usage 时无法计量；不以字符数换算收费。最近任务指标不含自动历史摘要请求，累计原生用量包含由任务服务统计到的摘要用量。
`images_attached` 只表示构建了带图消息，不是服务商确认接收数量。

实机设置页的一次测量为 **19859 → 948 字符**（约减少 95.2%），未变回复 235 字符。这不是所有页面的固定比例，更不是整次任务节省 95.2% token；提示词、工具 schema、历史及图片仍有开销。

## 验证与使用建议

先试“打开设置 → 进入显示与亮度 → 报告当前页面，不修改设置”。普通界面可以用本任务授权。
只有遇到图标/自绘目标缺失，再决定是否开启视觉；付款、验证码、权限修改等仍交用户处理。
实际已验收和待验收项目见 [`VALIDATION.md`](VALIDATION.md)。

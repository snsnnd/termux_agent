# 核心、能力边界与手机优先的引擎复用

本文区分当前代码与后续建议；不代表已经接入 Pi/DSH 或获得系统额外权限。

## 1. 当前核心是什么

当前是一个轻量 Java 原生 agent，不包含自研大模型。模型推理由配置的外部 API 提供。

| 当前模块 | 已有职责 |
| --- | --- |
| `MainActivity` | 聊天、历史分页、配置、文件界面、人工确认 |
| `AgentService` | 模型/工具循环、上下文整理、任务生命周期、授权范围、取消和通知 |
| `ModelClient` | HTTPS 流式模型请求与工具调用结果组装 |
| `NativeTools` | 文件、Android App UID Shell、无障碍工具调度 |
| `BridgeService` | 无障碍观察/动作、同 App 多窗口、目标快照核对 |
| `AgentStore` | SQLite 会话和工作区、Keystore 密钥存储 |
| `AgentPolicy` | 工作区路径检查、审批分类、尽力识别敏感动作 |

当前工程核心是“模型循环 + Android 执行”。长期更值得保留的是 Android 执行层、明确的授权与个人工作流，通用 agent 循环可以复用成熟实现。

## 2. 现在能完整流畅操作手机所有内容吗

不能。已打通并验证了部分真实任务，不等于覆盖所有应用和系统功能。

| 能力 | 当前边界 |
| --- | --- |
| 界面读写 | 主要依赖 App 暴露的无障碍控件；自绘、游戏、部分 WebView/安全界面可能读不到 |
| 手机导航 | 已实现导航和控件/坐标动作；各第三方 App 未做完整回归 |
| 文件 | App 私有工作区及用户通过选择器导入的文件；不等于任意读取全盘或其他 App 私有目录 |
| 文档理解 | 有文件读写，不等于已支持 PDF/图片/OCR/音视频的完整解析 |
| 系统与个人数据 | 未集成通讯录、日历、通知监听等整套接口；不能视为已经拥有这些权限 |
| Shell | App UID 的 Android sh；不是 root、不是 Termux 工具链，也不是隔离安全容器 |
| 后台 | 任务服务可在后台运行，但通常仍操作前台可见的目标 App，不能与用户在同一屏幕无限互不干扰地操作 |
| 锁屏与私密界面 | 不能绕过锁屏、系统权限、受保护内容及 App 自身保护 |
| 流畅性 | 历史界面优化不等于操作零延迟；模型、网络、窗口动画和验证步骤都有耗时 |

当前版本的默认任务授权只减少普通界面操作的确认次数；高级免审批不改变 Android 授予的权限，也不能保证敏感行为识别完整。

## 3. 能否复用别的引擎

能，但必须做适配和实机验证，不能把现有 Java agent 直接改名为 Pi/DSH。

推荐目标：

```text
Android 原生交互、分享入口、任务列表与状态
                       |
                 引擎适配边界（待实现）
          轻量 Java / Pi SDK 或 RPC / 其他引擎
                       |
            Android 能力网关（待提取强化）
        权限、任务范围、风险确认、日志、停止与验证
                       |
       官方系统接口优先 / App 集成 / 无障碍兜底
```

Pi 官方提供 Node.js/Bun SDK 与进程集成接口，可以复用会话、上下文整理、工具及事件机制。
Java 客户端可通过受控子进程协议集成，或由 Node 侧适配器连接 SDK；仍需确定 Android 运行时、版本和依赖。
DSH 路线也应固定实际引擎版本、核对接口和许可证，不能把整个 DSH Go 客户端误当成一个可随意嵌入的 SDK。

Node 可评估 Android 兼容构建，或在 PRoot 用户态环境中运行；后者更接近 DSH Go 的本机路线，但体积、后台、子进程和升级管理成本更高。
PRoot 不是新内核、不是 root，也不是可靠的恶意代码隔离边界。

接入引擎时尤其要注意：如果同时给它不受限的 Shell 或同 UID 私有文件访问，它可能绕过仅存在于工具网关中的逻辑审批。
真正的隔离需要另行设计进程/UID/IPC 边界；不能声称套一个协议就安全了。

## 4. 怎样与手机接口深度绑定

不是申请所有权限，而是把明确的能力变成可验证、可授权的手机工具。

1. **系统入口**：接收 Android 分享的文本、链接或选中文件，直接创建带来源的任务；不要要求用户复制到聊天框。当前尚未实现分享接收入口。
2. **结构化能力优先**：优先使用 Intent、公开 Deep Link、系统编辑页和官方 API，减少模拟点击。日历提醒、打开导航、系统分享等适合走语义化接口。
3. **文件访问可控**：扩展 SAF/MediaStore 的合法 URI 授权；按需解析文档，不把“选中文件”误当成“可以读取全盘”。
4. **通知集成**：通知批准/拒绝用于当前任务；若未来接入通知监听/回复，应单独说明范围并取得用户授权，不能默认抓取全部通知。
5. **可靠执行**：统一排队、运行、等待、暂停、完成、失败、取消状态；记录动作 ID 与结果，执行前核对、执行后验证，结果不明时不盲目重放。
6. **手机交互**：可选浮动状态条、清楚的暂停/停止、返回任务结果；按 Android 权限及前后台限制实现，而不是靠强行后台弹窗。
7. **个人工作流**：先做少量高频闭环，例如“分享一个文件 → 按需解析 → 整理工作区 → 生成结果 → 系统分享”，再扩大覆盖。

差异化应由真实任务成功率、用户介入次数、耗时、恢复能力和权限范围来证明，而不是由工具数量或界面口号来证明。
开源、可改和使用无障碍也不是独家优势。

## 5. 建议迭代顺序

- 先稳定当前执行与数据迁移，补分页、通知审批、取消和任务授权的回归测试。
- 再提取引擎与 Android 能力之间的稳定接口，保持现有 Java 后端可用。
- 选择一个引擎做最小接入验证，不同时维护多套重型运行时。
- 随后优先做分享入口、结构化系统工具和一个手机专用闭环。

不在本次 Git 提交中擅自下载 Linux/Node 环境、迁移模型引擎或申请新的系统权限。
